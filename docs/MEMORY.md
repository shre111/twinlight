## Gotchas
- Node 24 is pinned in `.nvmrc`, but this machine's nvm default is 22: run `nvm use` (or prefix commands with it) before pnpm or just.
- TypeScript is pinned to 6.0: the native 7.0 has no JS API yet, which Next's build type-check and the NestJS CLI use.
- Biome 2.6 also formats Markdown and YAML; `biome.json` excludes those, `.claude/` and `design/` (D-018 scopes Biome to TS/JS/JSON).
- `next dev` writes `apps/web/AGENTS.md` unless `agentRules: false` (set). Next 16's own docs ship in `apps/web/node_modules/next/dist/docs/`; read them before relying on remembered APIs.
- Tokens: after editing `design/tokens.json`, run `pnpm -F @twinlight/ui tokens`; the freshness test fails otherwise. The colour guard doesn't catch named colours (`white`), and `href="#add"` would be a false positive.
- Fonts: `next/font/local` paths must be relative to the calling file (package specifiers fail under Turbopack), and the font variable classes must stay on `<html>`. The rupee sign is only in the latin-ext subsets: add latin-ext faces (`unicode-range`, `preload: false`) before Brief or Plan show prices.
- Phone stills: headless Chrome `--window-size` below about 500 px lays out wider; use viewport emulation (Playwright or CDP).
- Disk: the Mac disk filled twice (Docker hung on 2026-11-02; 687 MB free on 2026-11-09, when lane captures failed with ENOSPC) and Docker restarts need a laptop restart; restarting Docker means restarting the laptop. Check `df -h /` before big downloads. MinIO comes from `cgr.dev/chainguard/minio` pinned by digest (official images are gone).
- CI: `ci-ok` is the single status (it reports even when all jobs skip; docs-only PRs run only `changes`, `ci-ok` and the title check). The formats job also reruns on `py/tape/**`, `py/pack/**`, `fixtures/pack/**`, the stage pack reader and Node and uv toolchain changes, and runs the stage pack goldens (`pnpm -F @twinlight/stage exec vitest run test/pack-golden.test.ts`). The web job reruns on `fixtures/scenarios/**` (the timeline test reads the prototype scenario). The python matrix lists projects explicitly, so a new `tools/` dir must be added to it. `astral-sh/setup-uv` has no major tags; pin its exact release.
- Dev stack ports: this Mac runs native Postgres and Redis on 5432 and 6379, so the stack maps Postgres to 15432 and Redis to 16379 (all ports bound to 127.0.0.1). A `.env` copied before that still points at 5432/6379; update `DATABASE_URL` and `REDIS_URL` from `.env.example`. Grafana is on 3001.
- Compose: `up --wait` exits 1 if any started container exits (even with 0), so the bucket one-shot sits behind `profiles: [init]` and `just infra` runs it after. Images pulled while the disk was full can be silently corrupt (zero-byte files) and Docker reuses the layers; switch tags rather than prune others' images.
- Toy city: pin seed 49 in count checks (the prototype's own building count varies about 2.7% across seeds). Toy ties are one-way, so a few residents have under 3. The toy keeps the prototype origin; its bbox excludes the river ring (±6 km). Regenerate `data/cache/toy-48k` and `toy-5k` after any pack change (`uv run python -m twl_engine.fixtures --seed 49 --residents N --out DIR`).
- Goldens (D-023): CI runs NumPy at `X86_V3`, Numba generic without SVML, OpenBLAS Haswell single-threaded; `test_cpu_pin.py` fails strict runs otherwise. `just goldens` sets the same env and `python -m twl_engine.goldens --write` refuses without `TWL_GOLDEN_STRICT=1`; the `goldens` dispatch workflow uploads `hashes.toml` as an artifact to commit by hand (the workflow token is read-only). Hashes cover zstd bytes, so a `zstandard` bump needs regenerated goldens. Any change to `Scenario` or `Params` fields changes `scenario_hash`, `run_id` and every engine golden. The empty goldens never touch the RNG streams or the queue; P-012's must.
- Stage residents (Lane B): WebGPU draws `Points` at 1 px, so residents are one instanced `Sprite` with `PointsNodeMaterial`. Event times upload as float32 and NEVER rounds to 2^32, which keeps ramps at zero. Halos are flare-only until P-045 bloom (remove them then). Sprites on walls need a depth nudge toward the camera (capped at 60 m). SwiftShader costs about 10 µs per instance per frame; judge performance on a real GPU.
- P-045 must remove the resident glow stand-in from `packages/stage/src/layers/residents.ts` when bloom lands: the second quad in `pointAndGlowQuads()` and `withGlow`, the `glow` attribute, `isGlow` and the constructor's `glow` option (and `TIERS[tier].bloomScale > 0` in `stage.ts`); the glow branches of `sizeNode`, `positionNode` (`offAxisCos`, the `cameraNear` import) and `colorNode`; the `GLOW_*` constants, `glowDensity`, `settledGrowth`, `settledRadius`, `glowEnergy`, `glowPeak`; the `density` parameter of `#createMaterial` (it also scales `flareGain`, so decide if the halo stays); and the glow tests in `test/residents.test.ts`. Retune `FLARE_SPAN` (2.5), flare growth (1.2) and halo falloff (0.5) with bloom on; keep `MIN_PHYSICAL_PX`. If bloom lands weak, lower `GLOW_ENERGY` before deleting. Glow quads sit just past the near plane, so a hidden resident hazes the face in front of it; real bloom won't.
- Stage shaders (Lane B): use TSL `colorNode`/`opacityNode`, never `fragmentNode` (skips the sRGB output transform); mix shades on sRGB values, then convert. P-045 needs a sanitize pass before bloom (no per-fragment NaN guard exists) and output dither (dark gradients band on the real GPU). The colour guard also matches hex inside comments. three/webgpu and three/tsl load in Node, so vitest can test layers.

- Stage (Lane B): use `http://localhost:<port>`, not `127.0.0.1` (Next dev blocks it as cross-origin). Lane B's dev server runs on 3101. On an M4 the empty stage runs 16.7 ms p50; the prototype itself averages about 24 ms at 1837 px and DPR 1.75, so P-016 has to beat it. Shot baselines are macOS SwiftShader; CI needs Linux baselines (P-046).
- Tape fixtures: hand-built ones regenerate with `uv run python -m twl_tape.fixtures`; the engine one only through `just goldens`, together with `hashes.toml` (`test_tape_fixture.py` fails if they drift). `--check` relies on zstd output matching across platforms, so bump `zstandard` in its own PR with fixtures regenerated.
- `zstddec` never throws: a failed decode just returns a short or empty array. Always go through `decompressZstd`, which parses the frame header and checks sizes. Without a checksum flag zstd cannot detect a corrupt body, so tape sections rely on their crc32. A Node `Buffer`'s `slice` is a view: copy with `new Uint8Array(bytes.subarray(a, b))`.
- Tape v1 and engine core: the 352-byte header carries row counts and the reader sizes columns from them (`raw_length` is only a check; 8-byte padding hides small count errors). Empty sections are real zstd frames. `pop_until` returns an `Events` struct of arrays; hooks are `(state, streams, queue, start, end, events)`. Golden worker tests need at least as many seeds as workers (a pool spawns one process per pending task) and picklable module-level callables in `twl_engine.goldens` (test modules cannot be unpickled under `--import-mode=importlib`). Tick-loop baseline with no behaviour: 35 ms for 48k residents over 30 days.
- P-012 engine: `world.py` (static tables and per-resident draws), `state.py` (`Sim`), `awareness.py`, `wom.py` (two Numba kernels), `orders.py`; hooks are `(sim, streams, queue, start, end, events)` in `tick.HOOKS`, and P-013 appends its own. Fixture params (`paid_scale` 1.161, `q` 0.00658, `alpha_0` -6.092) are fitted values far from the section 11 defaults, which are not calibrated. Refit with `uv run python -m twl_engine.fit_prototype --write` (about 2 minutes), then `just goldens`. `load_scenario` rejects unknown keys and TOML cannot express `None`. The small golden fixture scales paid reach by 5,000/48,000. 0.65 s per seed at 48k, 1.4 s at 100k; time it on a cool machine. The session scratchpad is shared between agents; use a subdirectory.
- P-013 supply: `supply.py` (one Numba kernel walks a tick's arrivals, reviews and attempts in minute order), `SupplyStats` from `run_seed_with_stats`, golden inputs `supply_small`, `low_stock`, `slow_riders`. Without a supply block nothing changes, which the anchors rely on. An order-up-to level of zero means no restocking. The default (s, S) is fixed and does not follow demand, unlike the prototype's restocking, so it under-stocks late in the month. `build_supply_plan` builds residents-by-stores distance matrices: fine at 24 stores, chunk it before cities with hundreds. Travel noise goes through libm `exp`/`log` before a `ceil`, so supply goldens rely on the D-023 pin.
- Starlette's test client wants `httpx2`, not `httpx` (deprecation warning otherwise). pytest runs with `--import-mode=importlib`, so test module names may repeat across packages.
- The git hook rejects any Bash command containing a heredoc together with the words git and commit on one line, and it checks the current branch before a chained branch-create-then-commit command runs. Create branches, edit files and commit in separate calls.
- Gateway: NestJS 12 is ESM-only, so imports carry `.js` suffixes. There's no Nest CLI: dev runs through `@swc-node/register` and tests through `unplugin-swc`, because both emit decorator metadata (esbuild and tsx don't, which breaks DI). Biome needs `unsafeParameterDecoratorsEnabled` for it (override in `biome.json`). `NODE_ENV` defaults to production, so set `NODE_ENV=development` in `.env` for pretty logs.
- `/docs` and `/docs-json` are public; gate or disable them in production when auth lands (P-050).
- pnpm 10 skips dependency install scripts; `pnpm-workspace.yaml` lists the ones deliberately ignored. A new native dependency that needs its script goes in `onlyBuiltDependencies`.
- No branch protection on `main` (owner's choice for now); the git hook and squash-only repo settings are the only guards.
- The git hook blocks multi-line commit messages, heredoc messages, `--no-verify`, force pushes, commits on `main` and badly named branches. Use a single `-m "type(scope): subject"`. Squash-merge deletes the branch, so each PR of a point gets its own branch.
- `design/prototype/twinlight-city.html` is the visual reference for the stage (WebGL, single file, toy sim inlined). It is not production code; match its look, not its structure. Its scale clamps (point size, fog distance) were tuned by eye and are a good starting point for P-016.
- Shaders: never `pow()` a value that can go negative; it produced NaN black blocks on real GPUs in the prototype that headless renders did not show (DESIGN.md, shader rules).
- Workspace network may block CDNs and font hosts; stage visual tests must load three.js and fonts from node_modules.
